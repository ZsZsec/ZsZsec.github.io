bug bounty / web security

DOM XSS modal chain_

CWE-79Medium
Web SecurityDOM XSSReflected XSSJavaScript

Encontré este comportamiento durante pruebas autorizadas en un programa privado de bug bounty. El filtro público de un blog reflejaba el parámetro title dentro del área de filtros activos y permitía salir del contenedor original para inyectar un elemento nuevo.

La primera inyección no ejecutaba JavaScript por sí sola. El elemento añadido activaba el componente de modales del sitio, que recuperaba un atributo controlado y lo asignaba a innerHTML. Ese segundo parseo convertía HTML codificado en markup ejecutable y disparaba el payload al cargar la página.

El programa, el dominio, el identificador del reporte, la versión, el header requerido y los nombres propios están omitidos o sustituidos por valores sintéticos.

Una cadena de dos etapas

El parámetro title llegaba al filtro activo con suficiente control para cerrar el contenedor existente y crear otro elemento. Preparé ese elemento con los atributos que el JavaScript utilizaba para descubrir e inicializar modales:

procurement </div><div
  id=modal-probe
  data-modal=probe
  data-modal-close=&lt;details/open/ontoggle=alert(1)&gt;X&lt;/details&gt;
>BODY</div>

El atributo data-modal hacía que el componente tratara el nodo inyectado como un modal válido. El valor de data-modal-close permanecía codificado en esa primera representación, por lo que todavía no existía un elemento <details> ejecutable.

La segunda etapa aparecía durante la inicialización del componente:

var modalClose = self.getAttribute("data-modal-close");
// ...
closeBtn.innerHTML = modalClose;

getAttribute() devolvía el valor interpretado del atributo. Al enviarlo a innerHTML, el navegador lo parseaba de nuevo y generaba este nodo:

<details open ontoggle="alert(1)">X</details>

Como el elemento se creaba abierto, el evento toggle se disparaba sin que la persona tuviera que hacer otro clic.

Por qué funcionaba la sintaxis con barras

El valor inyectado utilizaba:

<details/open/ontoggle=alert(1)>X</details>

El parser HTML interpretaba las barras como separadores dentro de la etiqueta y terminaba creando los atributos open y ontoggle. El resultado relevante no era la forma original del string, sino el DOM normalizado por el navegador.

Esto también permitía mantener el payload compacto y sin espacios dentro del atributo que lo transportaba.

Reproducción anonimizada

La URL de prueba seguía esta estructura:

https://blog.example.test/blog?title=procurement%20%3C%2Fdiv%3E%3Cdiv%20id%3Dmodal-probe%20data-modal%3Dprobe%20data-modal-close%3D%26lt%3Bdetails%2Fopen%2Fontoggle%3Dalert(1)%26gt%3BX%26lt%3B%2Fdetails%26gt%3B%3EBODY%3C%2Fdiv%3E

Al abrirla, la página inicializaba el nodo inyectado, creaba su botón de cierre y ejecutaba alert(1) durante el segundo parseo.

El flujo completo era:

title controlado desde la URL
        ↓
breakout del filtro activo
        ↓
elemento inyectado con data-modal
        ↓
lectura de data-modal-close
        ↓
asignación a innerHTML
        ↓
creación de <details open ontoggle=...>
        ↓
ejecución de JavaScript

Respuesta inicial y DOM final

En la representación inicial, el contenido destinado al botón de cierre seguía codificado:

data-modal-close="&lt;details/open/ontoggle=alert(1)&gt;X&lt;/details&gt;"

Después de ejecutar el código del modal, el DOM contenía un elemento nuevo dentro del botón generado:

<div
  id="modal-probe"
  data-modal="probe"
  data-modal-close="&lt;details/open/ontoggle=alert(1)&gt;X&lt;/details&gt;"
  data-setup-modal="true"
  role="dialog"
  hidden
  tabindex="-1"
>
  BODY
  <button type="button" class="modal-close">
    <details open ontoggle="alert(1)">X</details>
  </button>
</div>

La diferencia entre ambos estados confirmó el límite de seguridad que fallaba: un valor que parecía inerte mientras estaba codificado se convertía en HTML activo cuando otro componente lo reutilizaba en un sink distinto.

Impacto

Una persona podía preparar un enlace público que ejecutara JavaScript bajo el origen de la aplicación cuando otra persona lo abriera. No se necesitaba autenticación y, después de navegar al enlace, el payload no requería interacción adicional.

No atribuí acceso adicional que no hubiera comprobado. Cualquier impacto posterior dependería de los datos y acciones disponibles para la víctima dentro de ese origen.

Remediación

El valor de title debe renderizarse como texto y no debe poder crear nodos dentro del filtro activo. Además, un componente no debería inicializar automáticamente elementos inyectados desde contenido controlado por la URL.

El texto del botón de cierre debe asignarse con textContent:

var modalClose = self.getAttribute("data-modal-close");
closeBtn.textContent = modalClose;

Si el producto necesita admitir HTML en ese atributo, debe aplicar una sanitización con allowlist inmediatamente antes del sink final. La CSP y el filtrado perimetral solo deberían tratarse como defensa adicional.

Estado del reporte

El reporte fue enviado al programa y permanece pendiente de revisión.
